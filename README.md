## Как это работает

Приложение рассчитано на один сценарий: владелец календаря заранее задан и заводит типы встреч, гость без регистрации записывается на свободный слот.

### Сценарий: от создания типа встречи до записи в списке владельца

1. Владелец открывает главную страницу и нажимает **«Начать работу»**.
2. На экране выбора он кликает **«Создать встречу»**.
3. В форме владелец заполняет тип встречи: **название**, **описание** и **длительность** (например, «Консультация», «Короткий созвон», 30 минут) и сохраняет его. Тип появляется в списке типов встреч владельца.
4. Владелец в любой момент может открыть список типов встреч и увидеть созданные записи — они хранятся в памяти процесса.

### Сценарий: запись гостя на встречу

1. Гость без регистрации заходит на сайт и нажимает **«Начать работу»**.
2. Выбирает **«Присоединиться ко встрече»**.
3. Выбирает нужный тип встречи из списка.
4. Открывается календарь на ближайшие **14 дней**: доступны часы работы владельца, шаг стартов соответствует настройкам в TypeSpec-контракте, длительность слота равна длительности типа встречи.
5. Гость выбирает свободный слот и записывается — встречу нельзя записать дважды, даже если она разного типа.
6. Запись встречи мгновенно появляется в списке предстоящих встреч у владельца.

> **Ограничение:** данные хранятся в памяти процесса, поэтому перезапуск сервера сбрасывает типы встреч и записи.

## Стек

- Бекенд: Java 21, Spring Boot 4.1, Maven
- Фронтенд: React 19, Vite, TypeScript, Tailwind CSS 4, shadcn/ui
- Хранилище: in-memory (в памяти процесса; PostgreSQL запланирован отдельным шагом)
- Тесты: JUnit 5 (дымовой), Vitest (дымовой)
- Окружение: mise (версии, задачи, daemons)
- CI: GitHub Actions → `mise run check` на каждый push
- Коммиты: Conventional Commits

Архитектурные решения: [docs/decisions.md](docs/decisions.md). Правила проекта для агентов: [AGENTS.md](AGENTS.md).
