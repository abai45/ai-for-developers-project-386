# 4. In-memory хранилище до отдельного шага с PostgreSQL

- Статус: принято (26.10.2026; ограничение зафиксировано в README)
- Источник: `docs/decisions.md`, AGENTS.md

## Контекст
Учебный проект без авторизации; персистентность не в скоупе спецификации #6, но API и правила расписания должны быть готовы к замене хранилища.

## Решение
Типы встреч и встречи живут в памяти процесса (`EventTypeStore`, `MeetingStore` в подпакете `store`). Перезапуск/редеплой контейнера сбрасывает все данные — это задокументировано в README. Репозитории изолированы от HTTP-слоя: переход на PostgreSQL — замена слоя `store` без изменения контроллеров и контракта.

## Последствия
- Демо на Render сбрасывается при каждом редеплое (принято осознанно).
- Тесты не зависят от пакетов благодаря HTTP-шову.
