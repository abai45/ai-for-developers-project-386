# Решения по контракту

Документ фиксирует архитектурные решения проекта «Календарь звонков» на этапе проектирования.
Используется как источник истины при написании TypeSpec-контракта и реализации.

## Параметры расписания

| Параметр | Значение |
|---|---|
| Часовой пояс владельца | `Asia/Almaty` (UTC+5, без перехода на летнее время) |
| Часы работы владельца | `09:30` – `18:00` |
| Окно записи | ровно **14 календарных дней**: со следующего дня включительно, последний день — «завтра + 13»; интервал `[сегодня+1д 00:00, сегодня+15д 00:00)` |
| Длительность слота | равна `durationMinutes` выбранного типа встречи |
| Шаг старта слотов | задаётся для каждого типа отдельно — `slotStepMinutes` |
| Пересечение интервалов | запрещено, включая частичное наложение, **между типами в том числе** |
| Касание интервалов | разрешено: новая встреча может начинаться в момент окончания предыдущей |
| Одновременные запросы | проверка на пересечение и создание брони выполняются атомарно |
| Гость | вводит имя (`guestName`, обязательное поле) |
| Владелец | один, задан в приложении константой; авторизации нет |

### Правила расчёта слотов

- Свободные старты для типа: `09:30 + k × slotStepMinutes`, пока `старт + durationMinutes ≤ 18:00`.
- Слот считается свободным, если его интервал `[старт, старт + длительность)` не пересекается ни с одной существующей бронью любого типа.
- Пример шага: «Короткий созвон» 15/15 → старты 09:30, 09:45, …; «Воркшоп» 60/60 → 09:30, 10:30, ….

### Валидация типа встречи

- `name` — 1–100 символов (непустая строка)
- `description` — до 500 символов, может быть пустым
- `durationMinutes` — от 1 до 510 (= длина рабочего дня 09:30–18:00)
- `slotStepMinutes` — от 1 до `durationMinutes`

## Решения по API (интервью 26.10.2026)

- **Время в API** — ISO-8601 с явным смещением владельца: `2026-10-27T09:30:00+05:00`
- **Слоты для гостя** — эндпоинт возвращает **все** слоты окна со статусом `free` / `occupied` (без данных гостя); при бронировании перепроверка на сервере → `409`
- **Список встреч владельца** — только предстоящие (`start ≥ сейчас`), по возрастанию
- **Скоуп операций** — только: создать тип, список типов, слоты, забронировать, предстоящие встречи. Отмена брони и редактирование/удаление типов — **вне скоупа**
- **Ошибки** — RFC 9457 `application/problem+json`
- **Успешное бронирование** — `201 Created` + полное тело встречи
- **«Подключиться ко встрече»** = записаться на свободный слот; отдельного экрана входа в встречу нет

## Роли (корректировка 26.10.2026)

В проекте две условные роли, авторизации нет:

- **Владелец** — один заранее заданный профиль, используется в админской части; создаёт типы событий и видит страницу предстоящих встреч (все типы одним списком)
- **Гость** — бронирует слоты без аккаунта и входа; видит список типов событий (название, описание, длительность), выбирает тип, затем свободный слот на 14 дней и создаёт бронирование

**Доступ владельца** — карточка «Создать встречу» гостям не показывается; владелец заходит по прямой ссылке `/owner`, в футере — тонкая ссылка «Владелец».

## Главный экран (интервью 26.10.2026)

Первая фича — статические экраны без API.

- **Название** — «Календарь звонков»; `<title>`: «Календарь звонков — бронирование встреч за минуту»
- **Маршруты** — React Router: `/` лендинг, `/book` — выбор типа и запись гостя (сейчас заглушка «Присоединиться ко встрече»), `/owner` — админская часть владельца (заглушка «Создать встречу»); экрана `/start` нет — он был лишним шагом
- **Текст лендинга** — дословно из задания: заголовок «Сервис для создания и бронирования встреч за минуту: Указывайте тип события, время и продолжительность.» + кнопка «Начать работу» → `/book`
- **Доступ к админке** — ссылка «Владелец» в футере (не из лендинга и не из меню) → `/owner`
- **Стиль** — светлая тема shadcn (нейтральная, Geist), без переключателя тёмной темы; адаптивность через Tailwind-утилиты
- **Язык UI** — русский
- **Скоуп** — чисто фронтенд: бекенд и API не трогаем, моков нет

## Модель данных (черновик)

```
EventType   id, name, description, durationMinutes, slotStepMinutes
Booking     id, eventTypeId, guestName, start, end
            end = start + durationMinutes, вычисляется на сервере
```

## API-эндпоинты (черновик)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/event-types` | создать тип встречи (владелец) |
| GET | `/api/event-types` | список типов встреч |
| GET | `/api/event-types/{id}/slots` | слоты окна на 14 дней вперёд, статус `free` / `occupied` |
| POST | `/api/bookings` | записаться: `{ eventTypeId, guestName, start }` |
| GET | `/api/bookings` | предстоящие встречи владельца |
| GET | `/api/health` | дымовой эндпоинт, отвечает 200 |

Коды ошибок: `400` — невалидные параметры, `404` — неизвестный тип встречи,
`409` — слот занят или интервал пересекается с существующей бронью.

## Стек

| Слой | Решение |
|---|---|
| Бекенд | Java 21 (LTS) + Spring Boot 4.1.x + Maven |
| Контракт | TypeSpec → OpenAPI 3.1 |
| Серверная генерация | openapi-generator: интерфейсы контроллеров и DTO, логика — вручную |
| Фронтенд | React + Vite + TypeScript + Tailwind + shadcn/ui |
| Клиентский SDK | openapi-typescript + openapi-fetch |
| Хранилище | **in-memory** (в памяти процесса): перезапуск сбрасывает данные — ограничение указано в README.md, как требует задание. PostgreSQL запланирован отдельным шагом при появлении необходимости |
| Тесты | JUnit 5 (дымовой тест: приложение поднимается и отвечает) + Vitest |
| Линтеры | Spotless + Checkstyle (Java), ESLint + Prettier (TS) |
| Окружение | mise: версии инструментов, задачи `setup` / `check` / `dev`, daemons, git-хуки через hk |
| CI | GitHub Actions → `mise run check` на каждый push |
| Коммиты | Conventional Commits |
