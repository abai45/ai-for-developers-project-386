# Решения по контракту

Документ фиксирует архитектурные решения проекта «Календарь звонков» на этапе проектирования.
Используется как источник истины при написании TypeSpec-контракта и реализации.

## Параметры расписания

| Параметр | Значение |
|---|---|
| Часовой пояс владельца | `Asia/Almaty` (UTC+5, без перехода на летнее время) |
| Часы работы владельца | `09:30` – `18:00` |
| Окно записи | ровно **14 календарных дней**: со следующего дня включительно, последний день — «завтра + 13»; интервал `[сегодня+1д 00:00, сегодня+15д 00:00)` |
| Длительность слота | равна `durationMinutes` выбранного типа встречи |
| Шаг старта слотов | задаётся для каждого типа отдельно — `slotStepMinutes` |
| Пересечение интервалов | запрещено, включая частичное наложение, **между типами в том числе** |
| Касание интервалов | разрешено: новая встреча может начинаться в момент окончания предыдущей |
| Одновременные запросы | проверка на пересечение и создание брони выполняются атомарно |
| Гость | вводит имя (`guestName`, обязательное поле) |
| Владелец | один, задан в приложении константой; авторизации нет |

### Правила расчёта слотов

- Свободные старты для типа: `09:30 + k × slotStepMinutes`, пока `старт + durationMinutes ≤ 18:00`.
- Слот считается свободным, если его интервал `[старт, старт + длительность)` не пересекается ни с одной существующей бронью любого типа.
- Пример шага: «Короткий созвон» 15/15 → старты 09:30, 09:45, …; «Воркшоп» 60/60 → 09:30, 10:30, ….

### Валидация типа встречи

- `name` — 1–100 символов (непустая строка)
- `description` — до 500 символов, может быть пустым
- `durationMinutes` — от 1 до 510 (= длина рабочего дня 09:30–18:00)
- `slotStepMinutes` — от 1 до `durationMinutes`

## Решения по API (интервью 26.10.2026)

- **Время в API** — ISO-8601 с явным смещением владельца: `2026-10-27T09:30:00+05:00`
- **Слоты для гостя** — эндпоинт возвращает **все** слоты окна со статусом `free` / `occupied` (без данных гостя); при бронировании перепроверка на сервере → `409`
- **Список встреч владельца** — только предстоящие (`start ≥ сейчас`), по возрастанию
- **Скоуп операций** — только: создать тип, список типов, слоты, забронировать, предстоящие встречи. Отмена брони и редактирование/удаление типов — **вне скоупа**
- **Ошибки** — RFC 9457 `application/problem+json`
- **Успешное бронирование** — `201 Created` + полное тело встречи
- **«Подключиться ко встрече»** = записаться на свободный слот; отдельного экрана входа в встречу нет

## Роли (корректировка 26.10.2026)

В проекте две условные роли, авторизации нет:

- **Владелец** — один заранее заданный профиль, используется в админской части; создаёт типы событий и видит страницу предстоящих встреч (все типы одним списком)
- **Гость** — бронирует слоты без аккаунта и входа; видит список типов событий (название, описание, длительность), выбирает тип, затем свободный слот на 14 дней и создаёт бронирование

**Доступ владельца** — карточка «Создать встречу» гостям не показывается; владелец заходит по прямой ссылке `/owner`, в футере — тонкая ссылка «Владелец».

## Спецификация приложения (интервью 31.10.2026)

Карта решений для согласованной спецификации (wayfinder).

- **Назначение** — полная спецификация: API-контракт **плюс** экраны, состояния и сценарии; реализация — отдельное усилие после согласования спеки
- **Форма артефакта** — TypeSpec в `spec/` → `docs/openapi.json`; экраны — единый `docs/spec/screens.md` с секцией на каждый экран (маршрут, цель, состояния, компоненты, API-вызовы, сценарии)
- **Язык** — идентификаторы контракта на английском, описания внутри контракта (`@doc`) и спека экранов — на русском
- **Админка владельца** — `/owner` одна страница с секциями: форма создания типа + список типов (read-only) + предстоящие встречи всех типов одним списком
- **Бронирование гостя** — `/book`: мастер из 4 шагов: тип → календарь → имя → подтверждение, с видимым прогрессом
- **Календарь слотов** — сетка месяца; референс макета: `docs/spec/references/03-book-event-type.png` (инфо-карточка слева, календарь в центре, список слотов дня с днями «Свободно»/«Занято» справа)
- **Состояния** — общий словарь: loading / empty / error (кнопка «повторить») / ok; 409 брони → «Слот только что заняли, выберите другой» + автоперезагрузка слотов
- **Подтверждение брони** — отдельный экран «Вы записаны» (тип, имя, начало–окончание, «На главную»); без каких-либо интеграций — проект учебный
- **Мета-секции спеки** — адаптивность (мобилка/десктоп) и базовая доступность (фокус, alt, заголовки)
- **CI** — `mise run check` включает компиляцию TypeSpec и проверку, что закоммиченный `docs/openapi.json` совпадает с генерацией

## Общие секции screens.md (вопрос карты #5, 31.10.2026)

- **Состояния** — своя четвёрка `loading / empty / error / ok` у **каждой секции экрана** (не страницы целиком): `loading` → скелетон (shadcn `Skeleton`); `empty` → заголовок + пояснение; `error` → «Не удалось загрузить данные» + кнопка «Повторить»; `ok` → контент
- **Канонические тексты** — «Загрузка…»; «Пока ничего нет» / предметно «Типов встреч пока нет», «Свободных слотов на этот день нет»; «Не удалось загрузить данные» + «Повторить»; `409` → «Слот только что заняли, выберите другой» + автоперезагрузка слотов; экраны уточняют только предметные вставки
- **Ошибки API** — `application/problem+json` (RFC 9457): `type: about:blank`, `title`, `status`, `detail` на русском; для `400` — массив `errors: [{ field, message }]` для подсветки полей формы; `404`/`409` — одним `detail`
- **Показ ошибок** — встроенное состояние `error` в упавшей секции, без глобального оверлея; секции независимы; `409` в мастере — сообщение у списка слотов, мастер не закрывается
- **Адаптивность** — mobile-first, единственный перелом `md` (768px): `/book` на десктопе три колонки по референсу, на мобилке вертикальная последовательность; `/owner` на мобилке один столбец, на десктопе «форма + списки»
- **Доступность** — видимый фокус (shadcn по умолчанию), один `h1` на экран без прыжков уровней, `alt` у содержательных картинок, `label` у всех полей, ошибки с `role="alert"` / `aria-live`
- **Компоненты** — база shadcn: `Skeleton`, `Button`, `Alert`, `Card`, `Label`, `Input`; кастом — только сетка месяца по референсу
- **Секции `screens.md`** — порядок: Общие правила → Лендинг `/` → Владелец `/owner` (#3) → Гость `/book` с экраном «Вы записаны» (#4)

## Контракт: структура и форма TypeSpec (вопрос карты #2, 31.10.2026)

- **Где живёт контракт** — исходники TypeSpec в `docs/spec/tsp/`: `main.tsp` (импорты, `@service`), `models.tsp`, `routes.tsp`, `errors.tsp`, `package.json` + lockfile (пины `@typespec/compiler`, `@typespec/openapi3`), `tspconfig.yaml`; генерат — `docs/openapi.json` (коммитится, дрейф-чек в `mise run check`)
- **Метаданные сервиса** — `@service({ title: "Календарь звонков API", version: "1.0.0" })`, OpenAPI 3.1
- **Операции** — `createEventType`, `listEventTypes`, `listSlots`, `createMeeting`, `listMeetings`, `healthCheck`; пути: `POST /api/event-types`, `GET /api/event-types`, `GET /api/event-types/{eventTypeId}/slots`, `POST /api/meetings`, `GET /api/meetings`, `GET /api/health`; query-параметров нет (окно и рабочее время зафиксированы на сервере); `health` отвечает `200` без тела
- **Нейминг** — `Booking` → `Meeting` (глоссарий запрещает «booking» для «Встречи»); черновики модели и эндпоинтов ниже исправлены на `Meeting` / `/api/meetings`
- **Модели** —
  - `EventType`: `name` required 1–100, `description` optional до 500 (отсутствует = пусто), `durationMinutes` 1–510, `slotStepMinutes` 1..`durationMinutes` (кросс-полевая проверка — серверная); в ответах вместе с `id`
  - `Slot`: `{ start, end, status: "free" | "occupied" }` — строковый enum; ответ эндпоинта слотов — голый массив слотов
  - `Meeting`: `eventTypeId`, `guestName` required 1–100, `start`; `end` — только в ответе, вычисляется сервером
- **Время** — `offsetDateTime` во всех моделях (→ OpenAPI `date-time`, Java `OffsetDateTime`, TS `string`)
- **Ошибки** — единая модель `ProblemDetails` с `@error` (`type: "about:blank"`, `title`, `status`, `detail` на русском; массив `errors: [{ field, message }]` для `400`); `application/problem+json` для всех `400`/`404`/`409`
- **Теги** — `event-types`, `meetings`, `health`; русские описания через `@tagDoc`; openapi-generator режет контроллеры по тегам
- **Двойная генерация** —
  - коммитим только `docs/openapi.json` и `frontend/src/lib/api/schema.d.ts` — оба с дрейф-чеком в `mise run check`
  - Java: openapi-generator-maven-plugin на `generate-sources`, конфиг `backend/openapi-generator.yml` (generator `spring`, `interfaceOnly=true`, `useTags=true`, `dateLibrary=java8`, Jackson); `basePackage: io.github.abai45.backend` → интерфейсы контроллеров в `...backend.api`, DTO в `...backend.model`; сгенерированный код не коммитится
  - TS: openapi-typescript из `docs/openapi.json` → `frontend/src/lib/api/schema.d.ts`; openapi-fetch-обёртка пишется руками (`frontend/src/lib/api/client.ts`)

## Главный экран (интервью 26.10.2026)

Первая фича — статические экраны без API.

- **Название** — «Календарь звонков»; `<title>`: «Календарь звонков — бронирование встреч за минуту»
- **Маршруты** — React Router: `/` лендинг, `/book` — выбор типа и запись гостя (сейчас заглушка «Присоединиться ко встрече»), `/owner` — админская часть владельца (заглушка «Создать встречу»); экрана `/start` нет — он был лишним шагом
- **Текст лендинга** — дословно из задания: заголовок «Сервис для создания и бронирования встреч за минуту: Указывайте тип события, время и продолжительность.» + кнопка «Начать работу» → `/book`
- **Доступ к админке** — ссылка «Владелец» в футере (не из лендинга и не из меню) → `/owner`
- **Стиль** — светлая тема shadcn (нейтральная, Geist), без переключателя тёмной темы; адаптивность через Tailwind-утилиты
- **Язык UI** — русский
- **Скоуп** — чисто фронтенд: бекенд и API не трогаем, моков нет

## Модель данных (черновик)

```
EventType   id, name, description, durationMinutes, slotStepMinutes
Meeting     id, eventTypeId, guestName, start, end
            end = start + durationMinutes, вычисляется на сервере
```

## API-эндпоинты (черновик)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/event-types` | создать тип встречи (владелец) |
| GET | `/api/event-types` | список типов встреч |
| GET | `/api/event-types/{eventTypeId}/slots` | слоты окна на 14 дней вперёд, статус `free` / `occupied` |
| POST | `/api/meetings` | записаться: `{ eventTypeId, guestName, start }` |
| GET | `/api/meetings` | предстоящие встречи владельца |
| GET | `/api/health` | дымовой эндпоинт, отвечает 200 |

Коды ошибок: `400` — невалидные параметры, `404` — неизвестный тип встречи,
`409` — слот занят или интервал пересекается с существующей бронью.
